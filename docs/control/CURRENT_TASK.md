## 2. 已批准的手動建立第一層

第一層固定四個生活目的入口：

1. 建立要長期管理的內容
2. 安排未來要注意或處理的事情
3. 記錄正在處理的事情
4. 補記已完成的事情

正式邊界：

- 四入口只負責新增。
- 不新增第五個「隨手記」入口；尚未分類、尚未知道日期的想法由入口 2 的「之後再安排」承接。
- 分類、模板、保養項目與步驟完整保留，但不增加到第一層生活目的入口。
- 修改、補充與處理既有資料，從搜尋、列表、詳細頁、履歷關聯或 AI 查詢結果進入。
- 鎖定產品邏輯，不鎖死介面表現；未經真實 App 操作的文案、版面、步驟與互動均標記為待實機驗證。

## 3. 共通建立規則

- 先以最低成立資料建立，再由使用者決定是否補充。
- 建立、補充、完成是不同概念；資料未填滿不等於尚未建立。
- 正式建立與正式補充必須可追溯到履歷。
- 建立成功後提供「先記錄／繼續補充」。
- 缺漏不一律催促；只有影響功能、安全、期限或權益時才提高提示層級。
- 系統可以提出後續思考方向，但不得未經確認自動建立提醒、排程、下一次安排或其他正式資料。

## 4. 三方工程權責

正式關係：

> 使用者決定，GPT 規劃與把關，Codex 施工與回報。

Codex 不得自行進行任何產品、流程、文案、資料模型、Schema、欄位必填性、預設值、提醒、排程、AI、自動化、刪除既有功能或範圍擴張決策。

遇到未定義事項、正式規格衝突、需要改資料契約或存在兩種以上會造成不同產品行為的合理方案時，必須停工回報，不得猜測。

完整規範以 `docs/control/04-development-rules.md` 第 14 節為準。
